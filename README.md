# PETSCII Robots (Apple IIgs port)

Attack of the PETSCII Robots (version 12), originally written by David Murray
(2020-2022) for the Commodore PET 4032 in KickAssembler, being ported to the
Apple IIgs.

## Layout

- `PETROBOTS12.ASM` / `BACKGROUND_TASKS.ASM` — original KickAssembler (PET) sources (kept pristine)
- `convert_kick_vasm.py` — KickAssembler -> vasm (6502 oldstyle) converter (driven by the Makefile)
- `PETROBOTS12.s` / `BACKGROUND_TASKS.s` — converted vasm sources (regenerated by `make`)
- `IIGS_KEYS.s` — IIgs keyboard reader (`READ_KEY`) that replaces the PET GETIN calls
- `IIGS_LOAD.s` — ProDOS 8 MLI file loader (`PLAT_LOAD_FILE`) that replaces the PET `JSR $F356`
- `deploy/` — game data for the IIgs disk: `TILESET` and `LEVEL-A` … `LEVEL-K` (from the Apple III port)
- `NTPMUSIC.s` — NinjaTrackerPlus music driver for the intro (`ntp_music_start`/`ntp_music_stop`)
- `ntp/` — converted NTP songs (`robot attack.ntp` is the default title song) and `NTPPLAYER.bin`
- `Makefile` (`make petrobots`) — converts and assembles the PET game into
  `petrobots.bin` (a bare 6502 binary, origin `$0401`, ~18.2K)

The game is still Commodore PET code. Porting to the IIgs means replacing the
PET-OS and screen dependencies below.

## PET code that needs to be ported to the IIgs

### 1. Disk / level loading (file I/O) — done
`PETROBOTS12.ASM` loads the tileset and each level from disk using the PET
BASIC 4 loader (`TILE_LOAD_ROUTINE` / `MAP_LOAD_ROUTINE`, PET device-8 filename
block at `$D1`/`$DA`/`$DB`/`$D4` then `JSR $F356`).

On the IIgs this is replaced by `IIGS_LOAD.s`, which uses the **ProDOS 8 MLI**
(`OPEN`/`READ`/`CLOSE` at `$BF00`, emulation mode) through a 1K bank-0 buffer at
`$4C00`. `TILE_LOAD_ROUTINE` / `MAP_LOAD_ROUTINE` now just set `LOAD_NAME` /
`LOAD_DST` / `LOAD_LEN` and `JMP PLAT_LOAD_FILE`, which skips the file's 2-byte
PET load-address header and reads the payload straight to the game RAM (tileset
-> `$5000`, `$0B00` bytes; level -> `$5D00`, `$2300` bytes, so the 8K map lands
at `$6000`). Pathnames are `/PETSCIIROBOTS/TILESET` and
`/PETSCIIROBOTS/LEVEL.A` (the level letter patched at runtime).

The data (from the proven Apple III port) is kept in `deploy/` and placed on
`petsciirobots.dsk` by `make dsk` as the ProDOS BIN files `TILESET` (aux
`$5000`) and `LEVEL.A` … `LEVEL.K` (aux `$5D00`).

### 2. KERNAL character/byte I/O
- `JSR $FFD2` (CHROUT) — print routines (e.g. `DISPLAY_LOAD_MESSAGE1`, ~line 273)
- Keyboard input — **done**: the converter rewrites every `JSR $FFE4` (GETIN)
  to `JSR READ_KEY` (from `IIGS_KEYS.s`), which reads the Apple IIgs keyboard
  soft-switches `$C000`/`$C010` directly and translates the resulting ASCII to
  the PETSCII codes the game compares against (arrow keys -> `$11`/`$91`/`$1D`/
  `$9D` cursor codes; A-Z/0-9 pass through unchanged, since PETSCII upper-case
  matches ASCII). Note: the game's shifted keys (`#195` shift-C / `#205`
  shift-M cheats) and PET-only keys (RUN/STOP `#03`, HOME `#19`, custom-key
  entry via `#3A`) still need IIgs equivalents.

### 3. Interrupt/IRQ setup
`SETUP_INTERRUPT` / `RUNIRQ` (~line 300) install a PET IRQ handler via the PET
vector `$0090/$0091` and return through the PET IRQ entry `$E455`. On the IIgs
this must be rewritten for the 65816/IIgs interrupt controller and video IRQ.

### 4. Text screen output + PETSCII encoding
- Text is written directly to the PET text screen (e.g. `STA $8190,Y`,
  `$819C,Y`) and via `$FFD2`.
- Strings are `!SCR` (PET screen codes) / `!PET` (PETSCII) — see the
  `!SCR`/`!PET` data blocks. On the IIgs these must be re-encoded for the
  IIgs text/character set and written to IIgs video memory (or the SHR
  back-buffer used by the intro loader).
- `PET_SCREEN_SHAKE` and the border-flash code are PET-specific.

### 5. Memory map / zero page
PET-specific memory assumptions that must be mapped onto the IIgs:
- Program origin `$0401` and PET BASIC 1 `SYS 1037` stub
- Game data arrays `$5000`–`$5FFF` (destruct path, tiles, units, map..., 8K
  `MAP` at `$6000`)
- PET zero page scratch `$23`–`$39`, filename block `$D1/$DA/$DB/$D4`, pointers
  `$FB/$FC`, cursor `$31/$32`

### 6. Runtime environment
The PET program runs under the PET KERNAL (no OS). The IIgs build should run
under ProDOS 8 so the MLI file calls, keyboard, and video can be driven
through a thin IIgs BSoS/I/O layer.

## Current IIgs work
The `intro` loader (vbcc 65816, `make` default) already demonstrates the SHR
shadowed-memory fast-refresh path used to display `introscreen.png` on
`petsciirobots.dsk` (ProDOS 800K volume `PETSCIIROBOTS`).

**MOD music playback:** the intro plays a MOD soundtrack using
**NinjaTrackerPlus (NTP)**, Ninjaforce's Apple IIgs MOD player. The NTP engine
(by Jesse Blue) is a 65816 sound-interrupt-driven player whose API is a set of
`JSL`s (`NTPprepare` / `NTPplay` / `NTPstop` / `NTPsetplayvolume` /
`NTPgetsongpos`/`NTPgetvuptr`). It requires an `.NTP` song (converted from an
Amiga MOD) loaded into memory and copies the instruments into the DOC sound
RAM.

How it is wired up:
- `NTPMUSIC.s` (`ntp_music_start()` / `ntp_music_stop()`, called from `main.c`)
  loads two files at runtime from the `PETSCIIROBOTS` volume through the
  **ProDOS 8 MLI** (`OPEN`/`READ`/`CLOSE` at `$BF00`, emulation mode):
  - `/PETSCIIROBOTS/NTPPLAYER` — the NTP player engine (from the official
    release, `ntp/NTPPLAYER.bin`), loaded to `$0F0000`;
  - `/PETSCIIROBOTS/TITLE.NTP` — the title song (default `ntp/robot attack.ntp`,
    selectable via `make dsk NTP_SONG=...`), loaded to `$100000` through an
    8K bank-0 staging buffer with automatic 24-bit bank rollover.
- The engine is then driven with `NTPprepare` (instruments into DOC sound
  RAM + sound-interrupt install at `$E1002C`), `NTPsetplayvolume(180)` and
  `NTPplay` (loop), and torn down with `NTPstop` when a key is pressed.
- The player is tiny enough that the game loop keeps running while it plays;
  the song consumes the DOC sound interrupt, not the game's cycles.

**Hardware requirement:** 2 MB or more of RAM on the IIgs (the engine runs
from bank `$0F` and the song from banks `$10/$11`).

Making a new title disk with a different song:

    make dsk NTP_SONG="ntp/lose.ntp"

Available songs are the converted MODs in `ntp/` (get psyched, lose,
metal heads, metallic bop amiga, robot attack, rushin in, soundfx, win).
